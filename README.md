# Crawling Engine (Python)

公的資格・民間資格サイトの情報を自動収集・構造化し、**標準JSON出力**を生成するクローリングエンジンです。
運用観点における**「例外処理・エラー制御（タイムアウト／再試行／スナップショット）」**と、**ログベースの再現性／トラブルシューティング**を最優先に設計しました。

Pipeline: fetch → parse → normalize → output(JSON)

## 📌 プロジェクト概要
- 資格情報が複数のサイトに分散しており、管理が困難であるという課題からスタート
- 公的資格・民間の資格データを標準JSON構造へ統合・一元化
- 例外処理（エラー制御）と再処理を考慮したクローリングパイプラインの設計

## 📦 成果物 (Output)
- 成果物は、特定の作業ルート（`--root`）配下に生成されます
  - 例: `Certificate_api/1320/1320.norm.json`

## ⚙️ 設計のポイント (Architecture Points)
- 公的資格（Q-Net）／民間サイトの**「構造的な違いをパイプラインレベルで分離」**し、拡張性を確保
- adapter / util レイヤーに切り分けることでルールを分離し、**「保守性とデータ品質」**を最優先
- **「タイムアウト・再試行・スナップショット（HTML保存）・重複除去」**による徹底した失敗ケースの制御

## コード読み込みガイド
- `public_cert_api/` : 公的機関(Q-Net)クローラー集
- `private-cert-crawl/` : 民間/私設クローラー集

## セキュリティ
- クッキー、トークン、アカウント情報はリポジトリにコミットしません。(`cookies.txt`、`.env` などは `.gitignore` で処理)
- 過度なトラフィックを誘発しないよう、リクエスト間隔および再試行(リトライ)回数を制限しています。

## 詳細設計の背景および問題解決プロセス

### 1. プロジェクト開始の背景

Q-Net（キューネット）や資格証ネットなどの既存の資格試験サイトは 日程、試験情報、CBT機能がそれぞれ分散しており
ユーザーが関心のある資格だけを集めて一目で管理することが難しいという不便さがありました。

そこで、チームメンバーとの議論の末、単に情報を集めることにとどまらず、データを正規化し
インフラを直接構築する経験を積みたいという思いから、

資格試験の日程・試験情報・CBT・お気に入り機能を一つのサービスに統合して提供しようという結論に至り, 
これを卒業作品のテーマに選定しました。

---
## 2. 課題 ① クローリングパイプラインの設計

最初に直面した課題は、単なるクローリングの実装ではなく、
**「インターネット上に分散した情報を、どのような構造で収集・整理するか」**という設計の領域でした。

そこで、
**fetch (HTML収集) → parse (JSON変換) → normalize (正規化およびDB格納)**
以下のような共通パイプラインを基準に全体のアーキテクチャを設計しました。

また、サイトごとに異なるHTMLの構造や規則の差異を吸収するため、**「adapter階層」**を導入しました。
これにより、不要な文字の除去、空値（Null値）の処理、フォーマットの統一といった共通処理は**「utilスクリプト」**として分離し、
効率的に管理できるようにしました。

---

### 3. 課題 ② 公的資格・民間資格におけるデータ構造の違い

公的資格（Q-Net）と民間資格サイトは、データ構造および信頼性の面で 性質が大きく異なっていました。

この問題を解決するため、両者を同一のルールで 処理せず、パイプラインレベルで分離する設計を採用しました。

民間資格は構造が比較的安定しているため自動化の比率を高め、Q-Netについては「自動化可能な領域」と「手動検証が必要な領域」を 明確に区別して アプローチしました。

その結果、約 **80〜90%** のデータ整合性を確保し、完全な自動化よりも「運用可能性」と「データ品質」を優先する方針で実装範囲を設定しました。

当初は完全自動化を目指して取り組みましたが、Q-Netの不規則なデータ構造に直面して検討を重ねた結果、**「完全な自動化よりもデータの品質が 最優先」**であると 再認識することになりました。
これに伴い、複雑なアーキテクチャ設計の過程でGPTとも試行錯誤を重ね、AIが提案する効率的なコードと、自分が考える保守性のバランスを見極めながら、AIに依存せず最終決定を下すエンジニアとしての役割と責任を学びました。

### 4-2. 課題④: パーサーエンジンの高度化とデータ整合性の確保

9つの民間資格とQ-Net（公的資格）パイプラインのデータ精度およびシステムパフォーマンスを改善するために実施したリファクタリングのプロセスです。単にコードを修正するにとどまらず、環境間の干渉を最小限に抑え、データ品質を標準化することに注力しました。

* **発生した課題と技術的負債 (Technical Debt)**
   - **パースのボトルネック**：既存の `html.parser` エンジンが大容量DOM構造を処理する際に発生するパフォーマンス低下および特殊タグの解析エラーを確認
   - **データ汚染の残存**：公的/民間サイトの非構造化HTMLから流入する不要なタグ、特殊文字、異常な空白が最終的なJSON結果に含まれ、データ品質を低下させていた

* **エンジニアリング的解決策 (Engineering Solutions)**
   - **汎用パースエンジン（lxml）の導入**: 公的/民間のクローラー全体に `lxml` エンジンを全面適用し、パース速度を最適化。例外的なタグ構造に対する柔軟な対応力を確保
   - **中央集権型クレンジングモジュールの構築（民間）**: `engine_common/utils_text.py` 内に独立した `sanitize_text` 関数を設計。これにより、すべてのサブモジュールが同一のクレンジング規則に従う中央制御型アーキテクチャを実現
   - **公的パイプライン（Q-Net）の高度化**: 公的資格のコアロジックである `parse_tabs_min.py` に `sanitize_text` を統合適用し、数十個の試験タブから抽出されるテキストの品質を一括で正規化
   - **民間パイプラインの全面リファクタリング**：9つの民間資格個別クローラーの `get_text` オプションを標準化し、二重フィルタリングロジックを移植することで、成果物データの整合性（Data Integrity）を達成

* **段階的リファクタ링戦略 (Incremental Refactoring)**
  - **統合標準化** : 異なる構造を持つ公的/民間プロジェクトが `engine_common` ユーティリティを共有することで、**コードの重複排除と保守性の最大化**を実現
  - **環境間の整合性検証**：Fedora（Linux）と Windows 環境の双方で同一のクレンジング結果が得られるよう環境依存性を排除し、全数テストをクリア

> **「単なるクローリングにとどまらず、公的・民間のデータパイプラインを一つの洗練された標準に統合することで、システムの拡張性とデータの信頼性を 同時に確保しました。」**


## 5. Docker 기반 통합 인프라 및 멀티 플랫폼 지원

본 프로젝트는 단순한 코드 구현을 넘어, **'어떤 환경에서도 즉시 배포 및 실행 가능한 엔진'**을 구축하기 위해 Docker 기반의 통합 인프라를 도입했습니다. 이를 통해 Windows와 Linux 사이의 환경 의존성 문제를 완벽히 해결했습니다. 

| 항목 | 상세 내용 |
| :--- | :--- |
| **지원 OS** | Windows 10/11 (Docker Desktop), Fedora Linux (Docker Engine) |
| **인프라 표준화** | Docker Image를 통한 라이브러리 파편화 및 `psycopg2-binary==2.9.11` 적용으로 OS별 라이브러리 충돌 해결 |
| **리소스 최적화** | Shared Memory (2GB) 할당으로 대용량 자격증 페이지 수집 안정성 확보 |
| **구조적 유연성** | Host Volume Binding을 통해 기존 폴더 구조를 유지하며 컨테이너와 데이터 동기화 |
| **검증 완료** | 공공(Q-Net) 및 민간(KAIT) 자격증 데이터 정규화 테스트 통과  |

* **주요 엔지니어링 의사결정 (Decision & Rationale)**
  - **설계의 일관성**: 프로젝트의 기존 폴더 및 파일 구조를 강제로 변경하지 않고, docker-compose.yml의 볼륨 매핑 기능을 정교하게 설계하여 호스트의 소스를 컨테이너 내부 경로로 직접 연결했습니다. 이는 개발 생산성을 유지하면서도 운영 환경의 독립성을 확보한 핵심 전략입니다.
  - **환경의 제약 극복**: 리눅스(Fedora) 환경의 엄격한 보안 정책(SELinux)을 고려하여 :Z 플래그를 도입했고, 크롬 브라우저의 고질적인 메모리 부족(Tab Crashed) 문제를 인프라 레벨(shm_size)에서 근본적으로 해결했습니다.

단순히 작동하는 코드가 아니라, 어떤 운영환경(LINUX)에서도 돌아가게 만드는 엔진에 집중했습니다.
특히 윈도우와 페도라 사이의 라이브러리 충돌(psycopg2-binary)을 해결하며, 인프라 환경에 따른 
의존성 관리의 중요성을 배웠습니다.

### 💻 7-2. 분산 컨테이너 실시간 로그 수집 상태 (Loki & Promtail)
> **컨테이너 내부 및 파이프라인 전체에서 발생하는 다량의 텍스트 로그를 실시간으로 인덱싱하여 통합 관제하는 화면입니다.**

![배치 엔진 로그 시스템](./images/loki_log.png)

* **장애 추적 최적화:** 에러 발생 시 파일 서버에 일일이 접근할 필요 없이, Grafana 웹 콘솔 상에서 `error` 키워드 필터링을 통해 시스템 예외 원인을 초단위로 추적 및 디버깅할 수 있는 환경을 확보했습니다.

---

### 📑 메트릭 및 로그 수집 아키텍처
* **Prometheus & Pushgateway:** 크롤러 파이프라인의 메트릭(작업 성공률, 소요 시간 등)을 실시간 수집 및 저장
* **Grafana:** 수집된 메트릭 데이터를 시각화하여 대시보드로 시스템 상태 모니터링
* **Promtail & Loki:** 컨테이너 내부 및 시스템에서 발생하는 로그 데이터를 중앙집중형으로 수집하고 인덱싱하여 빠른 에러 디버깅 환경 확보

### 💡 주요 엔지니어링 의사결정 (Decision & Rationale)
* **시스템 가시성 확보:** 텍스트 로그를 일일이 확인하던 방식에서 벗어나, Grafana 대시보드를 통해 CPU/메모리 자원 및 파이프라인 상태를 시각적으로 한눈에 파악할 수 있도록 고도화했습니다.
* **장애 추적 시간 단축:** Loki와 Promtail의 도입을 통해 분산된 컨테이너의 로그를 한곳으로 모아, 시스템 예외 발생 시 원인 분석 및 예외 처리(Troubleshooting) 시간을 대폭 단축했습니다.

## 8. 환경 설정 가이드 (Environment Setup)

본 프로젝트는 원활한 개발 및 운영을 위해 두 가지 실행 환경을 제공합니다. 

* **Option 1 (가상환경):** 코드 수정 및 로컬 테스트 등 **개발 단계**에서 빠른 피드백을 위해 사용합니다.
* **Option 2 (Docker):** 실제 운영 환경과 동일한 조건에서 **엔진을 시연하거나 배포**할 때 사용하며, 환경 의존성 없이 즉시 실행 가능합니다. (권장)

## 1. Linux (Fedora 기준)
1. **시스템 패키지 설치**
   ```bash
   sudo dnf install gcc postgresql-devel
   ```

2. **가상환경 구축 및 의존성 설치**
   ```bash
   python3 -m venv .venv
   source .venv/bin/activate
   python -m pip install --upgrade pip
   pip install -r requirements.txt
   ```

3. **가상환경 활성화**
   ```bash
   source .venv/bin/activate
   ```

4. **엔진 실행(가상환경에서 공공 자격증 추출)**
   ```bash
   python -m public_cert_api.run_public --root "../cert_data" --jmcd 1320 --mode http
   ```

5. **엔진 실행(가상환경에서 민간 자격증 추출)**
   ```bash
   python run_once.py --cert [자격증이름] --config private-cert-crawl/configs/cert_map.yaml
   # 예: linux_master
   ```

6. **도커 설치(Linux 기준)**
   ```bash
   # 1. Docker 및 Docker Compose 설치
   sudo dnf install -y docker docker-compose

   # 2. Docker 서비스 시작 및 부팅 시 자동 실행 설정
   sudo systemctl start docker
   sudo systemctl enable docker

   # 3. (선택) sudo 없이 도커 사용을 위한 사용자 그룹 추가
   sudo usermod -aG docker $USER
   # 이후 로그아웃 후 다시 로그인해야 적용됩니다.
   ```

7. **엔진 빌드 (최초 1회 또는 코드 수정 시)**
   ```bash
   docker compose build
   ```

8. **엔진 실행 (도커에서 공공 자격증 추출)**
   ```bash
   JMCD=1320 docker-compose up -d public-engine
   ```

9. **엔진 실행(도커에서 민간 자격증 추출)**
   ```bash
   CERT=linux_master docker-compose up -d private-engine
   ```

10. **전체 종목 일괄 수집**
    ```bash
    while read -r jmcd; do 
         echo "▶️ 현재 수집 중인 종목 코드: $jmcd"
         JMCD=$jmcd docker-compose up public-engine
    done < others.txt
    ```

12. **보안 및 권한 관리**
    ```bash
    # 1. 소유권 변경 (현재 사용자로 지정)
    sudo chown -R $USER:$USER ~/cert_data

    # 2. 디렉토리 권한 (755): 리스트 조회 및 진입 허용
    find ~/cert_data -type d -exec chmod 755 {} +

    # 3. 파일 권한 (644): 읽기/쓰기 허용 (실행 방지)
    find ~/cert_data -type f -exec chmod 644 {} +

    # 4. SELinux 보안 라벨 (Fedora 등 특정 환경 필요 시)  
    sudo chcon -Rt svirt_sandbox_file_t ~/cert_data
    ```     

## 1. Windows
1. **Python 설치**
   ```bash
   winget install Python.Python.3.11
   ```

2. **가상환경 구축 및 의존성 설치**
   ```bash
   python -m venv .venv
   .\.venv\Scripts\Activate.ps1
   python -m pip install --upgrade pip
   python -m pip install -r requirements.txt
   ```

3. **가상환경 활성화**
   ```bash
   .\.venv\Scripts\activate
   ```
   
4. **엔진 실행(가상환경에서 공공 자격증 추출)**
   ```bash
   python -m public_cert_api.run_public --root "../cert_data" --jmcd 1320 --mode http
   ```

5. **엔진 실행(가상환경에서 민간 자격증 추출)**
   ```bash
   python run_once.py --cert [자격증이름] --config private-cert-crawl/configs/cert_map.yaml
   # 예: linux_master
   ```

6. **Windows 환경**
   - **Docker Desktop 설치**: Docker 공식 홈페이지에서 설치 파일을 다운로드하여 설치합니다.
   - **가상화 설정**: BIOS에서 Virtualization(VT-x/AMD-V)이 활성화되어 있어야 하며, WSL2 기반 설정을 권장합니다.
   - **실행 확인**: 터미널에서 명령어를 입력하기 전, 반드시 Docker Desktop 앱을 실행하여 'Engine Running' 상태인지 확인해야 합니다.

7. **엔진 실행 (도커에서 공공 자격증 추출)**
   ```bash
   $env:JMCD="1320"; docker-compose up -d public-engine
   ```

8. **엔진 실행(도커에서 민간 자격증 추출)**
   ```bash
   $env:CERT="linux_master"; docker-compose up -d private-engine
   ```


9. **전체 종목 일괄 수집(Windows 환경은 Docker 파일 시스템 동기화로 인해 대량 수집 시 속도가 매우 느려질 수 있으므로, 가급적 Linux 환경 사용을 권장합니다)**
   ```bash
   foreach ($jmcd in Get-Content others.txt) {
      Write-Host "▶️ 현재 수집 중인 종목 코드: $jmcd"
      $env:JMCD = $jmcd.Trim()
      docker-compose up public-engine
   }
   ```
